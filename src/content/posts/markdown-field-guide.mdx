Posts on this site start as Markdown files, and the build compiles them with MDX. Ordinary Markdown works, and a post can also reach for a React component when it needs one. I keep this page around as the reference I check when I forget which syntax this setup supports.

<Callout type="note" title="Source of truth">
  Everything below is rendered from a single MDX file in `src/content/posts`. The site compiles it
  at build time and serves static HTML.
</Callout>

Each section covers one part of the syntax. If you are looking for something specific, jump to [frontmatter](#frontmatter), [inline text](#paragraphs-and-inline-text), [tables](#tables), [code](#code), or [MDX components](#mdx-components).

## Frontmatter

Every post starts with a YAML block. The schema requires five fields and accepts two optional ones.

```yaml
---
title: "A post title"
description: "One sentence for listings and search results."
tags:
  - Markdown
  - MDX
draft: false
publishedAt: "2026-11-06"
updatedAt: "2026-11-08"
coverImage: "/images/cover.jpg"
---
```

`title` and `description` appear on the post page and in its metadata. `tags` power the filters on `/posts`. `draft: true` keeps a post out of the index, feed, sitemap, and direct route. `publishedAt` and `updatedAt` use `YYYY-MM-DD`, and `updatedAt` cannot be earlier than `publishedAt`.

`coverImage` is optional. When it points at a file, the build crops it to 1200 by 630 for social metadata and shows it at the top of the post. Without it, the build generates a social card from the title, tags, and date, and the post page skips the hero image.

## Paragraphs and inline text

Markdown handles the common inline styles: **bold**, _italic_, **_bold italic_**, ~~strikethrough~~, and `inline code`. A link can include a title that appears on hover, like [the CommonMark spec](https://commonmark.org "CommonMark specification"). GFM also turns a bare URL such as https://developer.mozilla.org into a link.

Backslashes keep punctuation literal: \*this is not emphasis\* and \`this is not code\`. HTML entities still work, so &copy; renders as a copyright sign.

A blank line starts a new paragraph. A single newline inside a paragraph is treated as a space, which keeps the source readable without adding visible breaks.

## Headings and anchors

Use `#` through `######`, though most posts stop at `####`. The build adds an id to every heading and wraps the text in a link. This line points back to [paragraphs and inline text](#paragraphs-and-inline-text). The id comes from the heading text, so changing a heading breaks any old links to it.

## Lists

Lists can be tight or loose. The examples below are tight. Add blank lines between items when each item needs more than one paragraph.

### Unordered lists

- One item
- An item with `inline code`
- An item with a [link](https://developer.mozilla.org)
  - A nested item
  - Another nested item
- A final item

### Ordered lists

The number in the source does not have to increase. This source uses `1.` for every item, and the browser numbers them in order.

1. Write the file.
1. Run the checks.
1. Publish the result.

A list can also start at a later number:

3. Pack the bag.
4. Check the map.
5. Leave.

### Task lists

- [x] Draft the post
- [x] Add images
- [ ] Update the sitemap
- [ ] Share it

Task lists come from GFM. The checkbox renders as a disabled input, so it reads as a status rather than a control.

## Tables

Pipe tables come from GFM. The separator row controls alignment, and the extra spaces in the source are only for readability.

| Feature     |    Syntax    | Supported |
| :---------- | :----------: | --------: |
| Bold        |  `**text**`  |       Yes |
| Italic      |   `*text*`   |       Yes |
| Strike      |  `~~text~~`  |       Yes |
| Inline code | `` `text` `` |       Yes |
| Footnotes   |    `[^1]`    |       Yes |

Wide tables scroll horizontally, and the wrapper keeps the page itself from scrolling on a phone.

## Code

Fenced code blocks are highlighted at build time. The language after the opening fence picks the grammar. A fence without a language falls back to plain text.

```tsx
export const Route = createFileRoute("/posts/$slug")({
  loader: async ({ params }) => {
    const post = await fetchPost({ data: { slug: params.slug } });
    if (!post) throw notFound();
    return post;
  },
});
```

Shell commands get the same treatment:

```bash
vp check
vp test
vp build
```

A small JSON example, braces and all:

```json
{
  "title": "Markdown, end to end",
  "draft": false,
  "tags": ["Markdown", "MDX", "Writing"]
}
```

A diff is often clearer than a sentence about the change:

```diff
- src/routes/posts.$slug.tsx
+ src/routes/posts/$slug.tsx
```

Shiki renders a light and a dark token set, and the stylesheet picks the right set for the current theme. The configured languages are `bash`, `css`, `diff`, `html`, `js`, `json`, `jsx`, `md`, `mdx`, `sh`, `text`, `ts`, `tsx`, and `yaml`.

## Images

Markdown image syntax produces a figure with generated AVIF, WebP, and JPEG versions. The build downloads remote images once and serves local files.

![A laptop, notebook, and coffee on a desk](https://images.unsplash.com/photo-1498050108023-c5249f4df085?auto=format&fit=crop&w=1200&q=80 "A workspace")

The quoted string in that syntax is a title attribute, not a visible caption. To show a caption under the image, use the `img` element and the `caption` attribute that this site's image plugin understands:

Images inside a sentence stay inline: the Markdown mark ![Markdown logo](https://raw.githubusercontent.com/github/explore/main/topics/markdown/markdown.png) renders at text size.

Add `priority` to an `<img>` or `<PostImage>` when the image is above the fold. It switches loading to eager and raises fetch priority. The optimizer creates variants at 480, 960, and 1440 pixels wide, skipping any size larger than the source.

## Footnotes

Footnotes come from GFM. A marker in the text records the note, and the note lands at the bottom with a link back.

The build compiles each post to static HTML before deployment, which keeps MDX out of the Worker.[^build] Images go through the same build pass.[^images]

## MDX components

Plain Markdown stops at static content. MDX lets a post render a component with props. This site exposes `Callout` and `PostImage` globally, so a post can use them without an import.

These callouts share one component with four variants: note, tip, warning, and danger.

<Callout type="tip" title="Tip">
  Keep posts in version control. A diff is the most useful editorial review tool there is.
</Callout>

<Callout type="warning" title="Watch the build">
  Remote images are fetched while the site builds. A dead URL fails the build instead of shipping a
  broken image.
</Callout>

<Callout type="danger" title="No runtime evaluation">
  Cloudflare Workers disallow `eval()` and `new Function`, so MDX is compiled at build time rather
  than parsed per request.
</Callout>

Raw HTML works as well. Keyboard keys are the usual example: press <kbd>Cmd</kbd> + <kbd>K</kbd> to search.

Native disclosure elements work too:

<details>
  <summary>Show the callout source</summary>

```mdx
<Callout type="tip" title="Tip">
  Keep posts in version control.
</Callout>
```

</details>

MDX also evaluates JavaScript expressions inside braces. The next sentence is computed at build time: {["Markdown", "MDX"].join(" and ")}. Keep expressions simple because they run during the build, not in the browser.

A comment leaves a note for yourself without rendering it: `{/* This stays out of the HTML. */}`.

## Escaping MDX syntax

MDX treats `<` as the start of a JSX element and `{` as the start of an expression. Wrap them in inline code when you want to show the character, or put a backslash before them: `\<` and `\{`. Curly braces inside fenced code need no escaping because code fences are not parsed as MDX.

Most posts can stay in Markdown. Captions, callouts, and computed values are the cases where I reach for MDX. I add new tricks to this file when I use them, so the examples match the code that renders them.
